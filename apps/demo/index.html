Read the architecture ↗
The underlying idea

A conversation is a stream.
Knowledge can cross it.

Nested chats inherit a conversation’s path. Parallel work needs each agent to choose the context relevant to its task, then know when that context changes.

Conversation inheritance

Useful continuity within a conversation tree. Cross-branch changes still need coordination.

Explicit context dependencies

Shared capsule v2

Each stream stays scoped. Versioned references show precisely what changed and who depends on it.

Loomplane coordinates the information between agents. It does not change how a language model reads its input window.

The product thesis

Make stale assumptions
visible before the handoff.

The first use case is concrete: one agent changes an API contract while another implements its consumer. The broader opportunity is a shared context layer across tools, repositories, and teams.

Explore the business thesis ↗
01

Start with a painful boundary.

API and UI agents need the same contract, with exact evidence and revisions.

02

Make the core useful and open.

Local storage, versioning, context packets, imports, and agent integrations are Apache-2.0.

03

Earn a managed-service business.

Managed sync, enterprise identity, policy, and deployment guarantees are the proposed paid expansion—not shipped capabilities.
